### Day7 执行结果

**代码改动**：

- `eval_agent.py`: 新增 `--query-mode simple|optimized` CLI 参数

**评测结果（20条，max_rounds=10）**：
| 指标 | Pipeline (优化后) | Agent | 倍数 |
|---|---|---|---|
| 可用率 | 25% | 95% | 3.8x |
| 成本/条 | ¥0.0024 | ¥0.0330 | 13.8x |
| 耗时/条 | 2.99s | 17.13s | 5.7x |

**关键发现**：
1. Query 优化**检索层生效**：BM25 hit rate 100%，所有样本均命中
2. **根本瓶颈是语料库覆盖**：17个测试客户中仅9个有语料（53%）
   - 有语料的客户（Global Import Ltd, Bauhaus, 杭州华筑等）→ Pipeline 可用 ✅
   - 无语料的客户（UK Interiors, Nordic Lighting 等13个）→ Pipeline 返回"无法确认" ❌
3. 系统行为正确：对无语料客户不编造，忠实度可控
4. Agent 优势来源：自主规划能绕过部分检索问题（95% vs 25%）

**根因分析**：
- Pipeline 依赖预置语料库 → 语料库小（21条）→ 覆盖不全 → 命中率低
- Agent 可动态构造更丰富的 query → 在同等语料下仍能拿到更多上下文
- **结论**：Pipeline 可用率低的主因不是 query 构造质量，而是**语料库规模不足**
